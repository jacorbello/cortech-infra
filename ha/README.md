# Home Assistant dashboard

The Overview page is auto-generated by HA's default strategy until a config is
stored, at which point HA hands control over permanently and stops adding new
entities for you. That stored config lives only in HA's `.storage`, invisible to
this repo — so it is generated here and pushed over the API instead.

```bash
python3 ha/overview-dashboard.py     # regenerate overview-dashboard.json
HA_TOKEN=$(ssh root@192.168.1.52 'cat /root/.ha-token') \
  python3 ha/apply-dashboard.py      # validate, back up, push
```

`apply-dashboard.py` needs the `websockets` package — Lovelace config is
WebSocket-only, the REST API cannot read or write it.

## Why a generator instead of checked-in YAML

Entity IDs are hard-coded on purpose. A dashboard built from live discovery
reshuffles itself whenever a device drops off the network, which is exactly when
you want the layout to stay put.

## Safety

- Every entity reference is validated against live state before saving. A typo
  otherwise renders as a silent "Entity not available" card. `FORCE=1` overrides.
- The existing config is written to `overview-dashboard.json.backup` (gitignored)
  before being replaced.
- Full rollback: Overview → pencil → three-dot menu → **Delete dashboard**. HA
  reverts to auto-generating it.

## Layout

Eight sections: alerts, climate, lights & plugs, people, network, printer,
media, system.

Cards that would sit dead are wrapped in conditionals rather than shown greyed
out — the TV when powered off, PSN "now playing" when idle, and the three update
entities when nothing is pending. The alerts section renders nothing at all
unless WAN is down, black ink is under 20%, or a backup is mid-run.
